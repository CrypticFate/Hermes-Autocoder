## Baseline Findings

- No GitHub merge endpoint or auto-merge mutation is called in the application. Local git merge in controller.py:254 updates a workspace only. The old seed helper patches the default branch directly and conflicts with I1.
- Owner authentication currently requires the token login to equal the repository owner (github.py:57); it is not a separate bot identity. No existing secret contents were inspected in this audit.
- Profile setup, baseline and post-implementation checks run via DockerRunner.command inside the builder (controller.py:338,343,360), not as subprocesses in the controller. A fresh read-only check container is still missing.
- Worker egress is available: compose workers network is not internal and worker.py:65 leaves it connected throughout execution.
- Hermes uses skip_memory=True and terminal/file tools (hermes_runner.py:40), but has no effective-config attestation or explicit auxiliary-model validation.
- Feedback from OWNER, MEMBER and COLLABORATOR associations is accepted (github.py:119) and inserted into builder prompts (controller.py:351), so non-operator instructions can reach builders.
- Alembic exists. autocoder init runs upgrade head (cli.py:39-45); migrations/versions/0001_initial.py freezes the initial schema. Use alembic downgrade with a configured database URL on a disposable copy to verify reversibility.
- This workspace has no root .git directory. Git status/history validation is unavailable; nested pilot checkouts exist under data/. Do not initialize or modify their history as part of the migration.
